# 設置の進め方（このリポジトリ版）

配布キット（`README_はじめに.md` / `SETUP_FOR_AI.md`）は「キットのフォルダを机の上に置いて、そこでClaude Codeを開く」前提で書かれています。
このリポジトリでは、キットを `tools/ai-hisho-discord/` に置いた形で同じことをします。この文書は、その差分と段取りだけをまとめたものです。

---

## まず知っておいてほしいこと

**AI秘書は「ずっと起きているパソコン」の中でしか動きません。**

Discordからの依頼を受け取る `bridge.mjs` は、動かしっぱなしにして待ち受ける仕組みです。
ブラウザ版のClaude Code（claude.ai/code）は、依頼のたびに使い捨てのクラウド環境を用意して、終わったら片付けてしまうため、**ここでAI秘書を常駐させることはできません**。

そのため設置は、次のどちらかで行います。

| どこで動かすか | 向いている人 | 手順書 |
|---|---|---|
| **自分のパソコン**（推奨） | まず試したい人。PCの中のファイルも見てほしい人 | `SETUP_FOR_AI.md` |
| Railway（レンタルサーバー） | PCの電源を気にしたくない人。月5ドル〜＋API従量課金 | `RAILWAY.md`（※未検証） |

配布元も「まずはパソコンでの常駐から試すこと」を勧めています。以下はパソコンで動かす前提で書きます。

## あなたがやること

### ステップ1: Discord側の下ごしらえ（スマホ・ブラウザだけで完結。PC不要）

先に済ませておくと、パソコンでの作業が短時間で終わります。`SETUP_FOR_AI.md` の手順1〜手順4にあたります。

1. **専用サーバーを作る**（既存のサーバーは使わない。誤爆防止のため）
   Discordの左端「＋」→「オリジナルの作成」→「自分と友達のため」→ 名前を決めて作成
2. **Botを作る**
   https://discord.com/developers/applications → 「New Application」→ 名前を付けて「Create」
   → 左メニュー「Bot」→ 下にスクロールして **「MESSAGE CONTENT INTENT」をON**
   （**これを忘れると、AIがメッセージの中身を読めず一切反応しません**）
3. **Botをサーバーへ招待する**
   左メニュー「OAuth2」→「URL Generator」
   → SCOPESで `bot` にチェック
   → BOT PERMISSIONSで `View Channels` / `Send Messages` / `Read Message History` / `Add Reactions` の4つにチェック
   → 下に出てきたURLをブラウザで開き、1で作ったサーバーを選んで「認証」
4. **IDを3つ控える**
   ユーザー設定 →「詳細設定」→「開発者モード」をON にすると、右クリックでコピーできるようになります。
   - サーバーID … サーバーアイコンを右クリック →「サーバーIDをコピー」
   - チャンネルID … 反応してほしいチャンネルを右クリック →「チャンネルIDをコピー」
   - 自分のユーザーID … 自分のアイコンを右クリック →「ユーザーIDをコピー」

   この3つは合鍵ではなく単なる番号なので、チャットに貼っても安全です。

5. **秘書の名前を決める**（例:「みらい」「はち子」など。この名前で返事をするようになります）

> **トークン（Botの合鍵）だけは、チャットにもリポジトリにも貼らないでください。**
> パソコンでの作業中に、コピーした状態のままAIに渡す方法があります（次のステップ）。

### ステップ2: パソコンで仕上げる

パソコンでこのリポジトリを開き、まず最新の状態にします。

```
git pull
```

そのうえで、リポジトリのフォルダで **Claude Code（パソコン版）** を起動し、こう伝えてください。

```
tools/ai-hisho-discord/SETUP_FOR_AI.md を読んで、Discord常駐を設置して。
キットは tools/ai-hisho-discord/ にあります。
```

あとはパソコン側のClaude Codeが、手順書に沿って1つずつ案内してくれます。
あなたがやるのは、ステップ1で控えたIDを貼ることと、トークンをコピーすることだけです。

**トークンの渡し方**: Developer Portalで「Reset Token」してトークンをコピーしたら、**貼り付けずに**「コピーしました」とだけ伝えてください。
パソコン側のClaude Codeが `node setup-helper.mjs write-token --from-clipboard` を実行し、クリップボードから直接
`~/.config/ai-hisho/bot-token`（権限600）へ保存します。チャット履歴にトークンは一切残りません。

### ステップ3: 許可の設定（手順6.5）

**この1つだけ、クラウド側からは作成できませんでした。** `.claude/settings.json` は「Claude Codeが何をしてよいか」を決めるファイルで、
AIが自分自身に権限を与える操作にあたるため、安全装置によって書き込みがブロックされます。判断はあなたに委ねられています。

やることは、リポジトリ直下に `.claude/settings.json` を作り、次の内容を入れるだけです（すでにファイルがある場合は `permissions.allow` の配列へ**追記**し、既存の項目は消さないでください）。

```json
{
  "permissions": {
    "allow": [
      "Bash(node -v)",
      "Bash(node --version)",
      "Bash(npm install)",
      "Bash(npm install:*)",
      "Bash(node bridge.mjs)",
      "Bash(node bridge.mjs:*)",
      "Bash(node setup-helper.mjs:*)",
      "Bash(node tools/ai-hisho-discord/bridge.mjs)",
      "Bash(node tools/ai-hisho-discord/bridge.mjs:*)",
      "Bash(node tools/ai-hisho-discord/setup-helper.mjs:*)",
      "Bash(claude --version)",
      "Bash(which claude)",
      "Bash(where claude)",
      "WebSearch",
      "WebFetch"
    ]
  }
}
```

**なぜ必要か**: Discordから依頼が届くたび、`bridge.mjs` は `claude -p ...` を**画面のない状態**で起動します。
画面が無いので「これをやっていいですか？」のダイアログを出す相手がいません。
事前に許可していない操作は、その場で諦めて「PCの前で承認をください」と返すしかなくなり、**後から許可を与える手段もありません**。
だから、調べ物・下書き作成のような「もともと自由にやってよい作業」を先に許可しておきます。

**入れてはいけないもの**（安全のため、あえて許可しません）:
`Bash(*)` のような丸ごと許可、`rm`・ファイルの削除や上書き、`git push --force`、SNSへの投稿、外部送信、支払いに関わる操作。
これらは今までどおり「承認をください」と返ってくる状態のままにします。

> パソコン側のClaude Codeに作らせても構いません（`SETUP_FOR_AI.md` の手順6.5にも同じ指示があります）。
> このクラウドセッションで作ってほしい場合は、そう言っていただければ作成します。

### ステップ4: テスト起動 → 自動起動

パソコン側のClaude Codeが `SETUP_FOR_AI.md` の手順6・6.6として案内してくれます。

- テスト起動: `npm install` → `node bridge.mjs` → Discordに「🍯 （秘書の名前）、起きました」が届けば成功
- 自動起動: Macは `node setup-helper.mjs autostart mac`、Windowsは `node setup-helper.mjs autostart win`

## `workdir`（作業させるフォルダ）について

設定ファイルの `workdir` には、AI秘書に作業してほしいフォルダの絶対パスを入れます。

**このリポジトリを指定すると**、安藤製菓サイトのコードや資料をAI秘書が読めるようになるので、
「注文ボットの仕様どうなってたっけ」「商品ページの文言を下書きして」といった依頼にスマホから答えられるようになります。
その場合、ステップ3の `.claude/settings.json` はこのリポジトリ直下に置くのが正解です（`workdir` と同じ場所である必要があります）。

サイトと関係ない調べ物だけに使いたい場合は、デスクトップに新しいフォルダを作ってそちらを指定してください。

## 検証済みの内容（クラウド側で実施）

配布物をそのまま置いただけではなく、実際に動かして次を確認しました。

- `bridge.mjs` / `setup-helper.mjs` … 構文エラー無し
- `node setup-helper.mjs check` … claude CLIの検出・キットの検出が正常に動作
- `node setup-helper.mjs write-config` … 必須項目の検証、`timeoutMs`（300000）と `sessionId`（UUID）の自動補完、権限600での保存を確認。不備のあるドラフトは正しく拒否
- `node setup-helper.mjs write-token` … 保存先と文字数だけを表示し、**トークンの中身は出力しない**ことを確認。権限600、前後の改行の除去、空ファイルの拒否も確認
- `bridge.mjs` の判定ロジック … 別サーバー・未許可ユーザー・対象外チャンネルを無視すること、@メンションなら対象外チャンネルでも反応すること、Discordの2000字制限に合わせた分割、@メンション表記だけを除去して本文の改行は保つこと（7項目すべて成功）
- `bridge.mjs` は `import` してもDiscordへのログインが走らない設計であることを確認

未検証: 実際のDiscordへの接続・自動起動の登録（どちらもあなたのパソコンでしか試せません）。`RAILWAY.md` の手順も配布元が未検証と明記しています。
