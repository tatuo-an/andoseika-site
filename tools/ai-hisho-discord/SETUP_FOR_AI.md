# これを読んでいるあなたへ

あなた（このファイルを読んでいるAI）は、これから持ち主のAI秘書をDiscordに常駐させる工事を行います。
このファイルは、その工事の完全な台本です。

## 大原則（工事全体で守る）

1. **持ち主は非エンジニア。** 専門用語は使わない。使うときは一言で説明を添える（例:「トークン（Botの合言葉のようなものです）」）。
2. **持ち主にコードを書かせない・黒い画面（ターミナル/コマンドプロンプト）を操作させない。** コマンドの実行はすべてあなたが行う。持ち主にお願いするのは「Discordの画面を見て、指示された場所をクリックする／コピーしたものを貼り付ける」ことだけ。
3. **1手順ずつ進める。** 1つの手順が終わったら、持ち主に「終わりましたか？」と確認してから次へ進む。急がない。
4. **トークン（Botの合鍵）の値をチャットに貼らせない。** 手順2に安全な受け渡し方法を書いてある。それに従う。
5. 詰まっても慌てない。**エラーはあなたが読み、あなたが直す。** 持ち主に「エラーメッセージを見てください」とは言わない。
6. **この工事の途中でClaude Codeの許可ダイアログ（「これをやっていいですか？」）が出たら、内容を持ち主に一言だけ伝え、問題なければ「常に許可」を選んでもらう。**「1回だけ許可」を選ぶと、同じ操作のたびにまた聞かれてしまう（「毎回聞かれる」という声の主因）。手順6.5で、常駐運転に必要な許可をまとめて設定ファイルへ書き込むが、それとは別に、工事中に出る個別のダイアログもその都度「常に許可」で答えていくこと。

工事が終わったら、このファイルとキット本体のファイル一式は、持ち主のフォルダに残しておいて構いません（次に何か直すときにまた読み返せるように）。

このキットには `setup-helper.mjs` という補助スクリプトが同梱されている。以降の手順で出てくる「設定ファイルを作る」「トークンを保存する」「自動起動を登録する」は、テンプレートの `{{...}}` を手で書き換えたりコマンドを1つずつ組み立てたりせず、この補助スクリプトを1コマンド呼ぶだけで完了する（依存パッケージなしで動くので `npm install` の前でも使える）。手順の中で使い方を都度示す。

## 手順0-A: 秘書の名前を、まず最初に決めてもらう

作業に入る前に、持ち主へ一番最初にこれを聞く:

> 「これから設置するAI秘書に、好きな名前を付けてください。呼び方は何でも構いません（例:『みらい』『はち子』など）。この名前で、あとで返事をするようになります。」

**この名前は持ち主が自由に決めるものであり、キット側で決まった固定の名前は存在しない。** もし持ち主が決めかねている場合だけ、あなたが2〜3案を提案してよい（決定権は持ち主にある）。決まった名前は控えておき、手順5（設定ファイルを作る）でそのまま使う。

## 手順0-B: 前提確認

まず、あなたが今動いている環境を確認する。

1. **OS判定**: 自分がMacで動いているかWindowsで動いているか判定する（`process.platform`相当。分からなければ持ち主に「WindowsですかMacですか」と聞いてよい）。
2. **Node.jsの確認**: `node -v` を実行する。
   - コマンドが見つからない場合: Node.js公式サイト（nodejs.org）からLTS版をインストールするよう案内する。持ち主が非エンジニアであることを踏まえ、インストーラのダウンロードページのURLを伝え、「ダウンロードしてダブルクリックし、指示に従って『次へ』を押していけば入ります」と説明する。インストール後、あなたが `node -v` で再確認する。
3. **claude CLIの確認とキットの場所の確認**: Node.jsが確認できたら、`node setup-helper.mjs check` を実行する。これ1つで、claude CLIの場所・キットフォルダ内の`bridge.mjs`の有無・設定ファイル/トークンファイルの有無をまとめて確認できる。claude CLIが見つからない場合はパスが通っていない可能性があるので、`which claude`（Mac）または `where claude`（Windows）で個別に確認してよい。`bridge.mjs`が見つからない場合は持ち主に「キットのフォルダの中でClaude Codeを開き直してください」とお願いする。

すべて確認できたら「準備は整いました。ここから設置を始めます」と伝えて次へ進む。

## 手順1: Discordの下準備

持ち主に確認する:
- [ ] Discordのアカウントを持っているか（無ければ discord.com で無料作成を案内する）
- [ ] スマホにDiscordアプリが入っているか（後で使う）

次に、**専用のサーバーを作る**よう案内する（既存のサーバーは使わない。誤爆と権限事故を防ぐため）。
1. Discordアプリ（またはブラウザ版）を開く
2. 左端の「＋」ボタン → 「オリジナルの作成」→「自分と友達のため」を選ぶ
3. サーバー名を決めて作成（例:「AI秘書室」）

サーバーが作れたら「できました」の返事をもらってから次へ進む。

## 手順2: Bot（あなたの受付窓口）を作る

これがこの工事でいちばん重要な手順です。1つずつ確認しながら進める。

1. 持ち主に https://discord.com/developers/applications を開いてもらう（Discordにログイン済みのブラウザで）
2. 右上の「New Application」ボタンをクリック → 名前を付ける（例:「AI秘書」）→ 「Create」
3. 左メニューの「Bot」タブを開く
4. 画面を下にスクロールし、**「Privileged Gateway Intents」**という項目を探す
5. **「MESSAGE CONTENT INTENT」を必ずONにする（これを忘れると、AIがメッセージの中身を読めず、一切反応しなくなります）**
6. 同じ画面の上のほうにある「Reset Token」（または「Token」の「Copy」）をクリックすると、長い文字列（トークン）が表示される

### トークンの安全な受け渡し方

トークンは「合鍵」です。チャットにそのまま貼ってもらうとチャット履歴に残ってしまうため、次のどちらかで進める。保存先（`~/.config/ai-hisho/bot-token`、フォルダ作成・権限600の設定込み）は、どちらの方法でも `setup-helper.mjs` が自動で行う。

**方法A（推奨・あなたがファイル操作できる場合）**: 持ち主に「その文字列をコピーしてください（貼り付けなくて大丈夫です）」とお願いし、次を実行する。

```
node setup-helper.mjs write-token --from-clipboard
```

このコマンドは、あなたが `pbpaste`（Mac）または `Get-Clipboard`（Windows）を個別に呼ばなくても、クリップボードの中身を直接ファイルへ書き込む（Mac/Windowsどちらでも同じコマンドでよい）。チャットには一切トークンが残らない。

**方法B（Aが使えない環境の場合）**: どうしてもチャットに貼ってもらう必要があるときは、その旨を先に伝える（「今回はチャットに一度だけ貼っていただきますが、履歴に残るため、設置が終わったら念のためDiscord側でトークンを再発行〈Reset Token〉することをおすすめします」）。貼ってもらった値は、チャットに再表示・再引用せず、一時ファイル（例: `token-temp.txt`）へ書き込んでから、次を実行する。

```
node setup-helper.mjs write-token token-temp.txt
```

実行後、`token-temp.txt` は削除する。

どちらの方法でも、コマンドの出力にはトークンの中身は一切表示されない（保存先と文字数だけが表示される）。あなた自身も `cat` や `type` でファイルの中身を画面に出さないこと（存在確認だけにとどめる）。

## 手順3: Botをサーバーへ招待する

1. 同じDiscord Developer Portalの左メニュー「OAuth2」→「URL Generator」を開く
2. 「SCOPES」で `bot` にチェック
3. 「BOT PERMISSIONS」で次の4つにチェック: `View Channels` / `Send Messages` / `Read Message History` / `Add Reactions`
4. 画面下に生成されたURLをコピーし、持ち主にそのURLをブラウザで開いてもらう
5. 招待先のサーバーで、手順1で作った専用サーバーを選び「認証」

Discordの持ち主のサーバーにBotが表示されたら完了。

## 手順4: 必要なIDを控える

Discordの「開発者モード」をONにすると、右クリックで各種IDをコピーできるようになる。

1. Discordアプリの「ユーザー設定」→「詳細設定」（Advanced）→「開発者モード」をON
2. **サーバーID**: サーバーアイコンを右クリック →「サーバーIDをコピー」
3. **チャンネルID**: AI秘書に反応してほしいチャンネル（例:「一般」）を右クリック →「チャンネルIDをコピー」（複数チャンネルで反応させたい場合は繰り返す）
4. **持ち主自身のユーザーID**: 持ち主のアイコン（左下やメンバー一覧）を右クリック →「ユーザーIDをコピー」

控えたIDは、チャットに貼ってもらって構わない（これらは合鍵ではなく、単なる識別番号なので安全）。

## 手順5: 設定ファイルを作る

`config.json.example` を参考に、次の内容のドラフトJSONを一時ファイル（例: `config-draft.json`）として、あなた自身のファイル作成機能で書き出す。

```json
{
  "guildId": "手順4のサーバーID",
  "channelIds": ["手順4のチャンネルID"],
  "allowedUsers": [{ "id": "手順4のユーザーID", "name": "持ち主の呼び名" }],
  "secretaryName": "手順0-Aで持ち主が決めた秘書の名前",
  "workdir": "作業させたいフォルダの絶対パス"
}
```

- `secretaryName` には、**手順0-Aで持ち主が決めた名前**をそのまま使う（このキットに固定の名前は無い。ここで初めて指定する）。
- `workdir` は、持ち主がAIに作業してほしいフォルダを指定する（分からなければ、このキットと同じフォルダ、またはデスクトップに新規フォルダを作って指定してよい）。
- `timeoutMs` と `sessionId` は省略してよい（省略すると `setup-helper.mjs` が既定値〈300000〉と新規UUIDを自動で補う）。

書き出したら、次を実行する。

```
node setup-helper.mjs write-config config-draft.json
```

これで `~/.config/ai-hisho/config.json`（Windowsは `%USERPROFILE%\.config\ai-hisho\config.json`）の作成・必須項目の検証・権限600の設定までがまとめて行われる。実行結果に保存した`secretaryName`・`workdir`・`sessionId`が表示されるので、意図した内容になっているか確認する。確認できたら、一時ファイル `config-draft.json` は削除してよい（秘密情報は含まないが、片付けとして）。

## 手順6: 依存パッケージのインストールとテスト起動

1. キットのフォルダで `npm install` を実行する
2. `node bridge.mjs` を実行する（フォアグラウンドで動かし、ログをその場で確認する）
3. ログに「起動しました。ログイン中: ○○」と出て、かつDiscordの指定チャンネルに「🍯 （秘書の名前）、起きました」というメッセージが届けば成功
4. 持ち主に、スマホのDiscordアプリからそのチャンネルへ「こんにちは」と送ってもらう
5. 👀のリアクションが付き、その後に返事が届けば**完了**（ここが工事の感動の山場です。持ち主に伝える）

**うまくいかない場合**は、慌てずログ（ターミナルに表示されているエラー文）を読み、下記「トラブルシュート」を参照して原因を特定してから直す。直したら、持ち主には「何が起きていて、何をしたか」を一言で説明してから再テストする。

テストできたら、いったん `Ctrl+C` でこのプロセスを止め、次の手順6.5（許可の設定）へ進む。

## 手順6.5: 許可の設定（ここをやらないと、常駐後に頻繁に止まります）

**なぜこれが必要か**: Discord経由でメッセージが届くたびに、`bridge.mjs` は `claude -p ...` を**画面のない状態（headless）**で起動する。画面が無いということは、許可ダイアログを表示する相手がいない、ということでもある。もし何か（Bashコマンドや調べ物など）を実行する許可がまだ与えられていなければ、常駐AIはその場で「許可がありません」と諦め、持ち主に「PCの前で承認をください」と返すしかなくなる。**しかもクリックできるダイアログ自体が存在しないので、後から許可を与える手段が無い。** これが、常駐させたAIが「毎回許可を求められる（ように見える）」といういちばんの原因になる。

だから、**常駐を始める前に、よく使う操作をまとめて許可しておく**。これで、調べ物・下書き作成・状況確認・集計のような、この秘書がもともと自由にやってよいとされている作業（`bridge.mjs`の安全設計を参照）が、いちいち引っかからずに進むようになる。

**進め方（あなたが行う）**:

1. このキットのフォルダ（`config.json`の`workdir`と同じ場所を推奨。分からなければキット自身のフォルダでよい）に `.claude/settings.json` があるか確認する。無ければこの後の内容で新規作成する。
2. 追記する内容を、次の一言で持ち主に説明し、OKをもらってから書き込む（コードを見せる必要はない）:
   > 「これから、AI秘書が調べ物や下書き作成のたびに毎回確認を求めなくて済むよう、よく使う操作だけを許可リストに登録します。ファイルの削除やSNSへの投稿のような操作は、この後も引き続き『承認をください』と聞いてくるようにしてあります。よろしいですか？」
3. OKをもらったら、次のJSONを `.claude/settings.json` へ書き込む。**すでにファイルがある場合は、中身を壊さず、`permissions.allow` の配列へこれらの項目を追記する**（既存の項目は消さない）。

```json
{
  "permissions": {
    "allow": [
      "Bash(node -v)",
      "Bash(node --version)",
      "Bash(npm install)",
      "Bash(npm install:*)",
      "Bash(node bridge.mjs)",
      "Bash(node bridge.mjs:*)",
      "Bash(node setup-helper.mjs:*)",
      "Bash(claude --version)",
      "Bash(which claude)",
      "Bash(where claude)",
      "WebSearch",
      "WebFetch"
    ]
  }
}
```

- 上のリストは、この設置手順（手順0-A〜手順6.6）と、常駐時に「調べ物」で使うツール（`WebSearch`・`WebFetch`）だけに絞ってある。**この工事・この常駐運転に実際に必要なコマンドだけ**なので、そのまま使ってよい。
- `node setup-helper.mjs:*` 1行だけで、トークン保存・設定ファイル作成・自動起動の登録/停止（内部で行うフォルダ作成・`chmod`・`launchctl`・`schtasks`の呼び出しを含む）がすべて許可される。個別に`mkdir`や`launchctl`、`schtasks`をリストへ足す必要はない（`setup-helper.mjs`が行う操作の中身は、この工事専用に決まった安全な処理だけに限定してある）。
- 持ち主が普段この同じフォルダで別の作業もしている場合や、`workdir`に別の常用コマンドがある場合は、その場その場で必要になった時点で個別に追記していけばよい（先回りして何でもかんでも足す必要はない）。
- 工事後にトラブルシュートで`launchctl unload`や`schtasks /delete`を直接叩きたくなった場合は、代わりに`node setup-helper.mjs stop mac`（Mac）または`node setup-helper.mjs stop win`（Windows）を使えば、追加の許可を求められずに済む。

**絶対にやってはいけないこと**:
- `"Bash(*)"` のような、コマンドを丸ごと許可する書き方は**しない**。必ず上のように具体的なコマンド名で絞る。
- `rm` ・ `rm -rf` ・ `git push --force` ・ファイルの削除や上書きにつながるコマンド、SNS投稿・外部送信・支払いに関わる操作は、**このリストに絶対に入れない**。それらは`bridge.mjs`の安全設計どおり、常駐AIが自分で判断せず「承認をください」と返す状態のままにしておく。

4. 書き込んだら、`.claude/settings.json` を一度読み直して、JSONとして壊れていないか（構文エラーが無いか）を確認する。

## 手順6.6: 自動起動の設定（PCを再起動しても自動で立ち上がるように）

### Macの場合（launchd）

1. 次を実行する。

   ```
   node setup-helper.mjs autostart mac
   ```

   これで、`templates/ai-hisho-launchd.plist.template` の `{{NODE_PATH}}`・`{{BRIDGE_PATH}}`・`{{BRIDGE_DIR}}`・`{{HOME}}` への値の埋め込み、`~/Library/LaunchAgents/com.ai-hisho.bridge.plist` としての保存、`launchctl load` の実行、`launchctl list`での登録確認までがまとめて行われる（再実行しても安全）。
2. 一度ログアウト・ログインするか、Macを再起動して、自動で起動メッセージがDiscordに届くか確認する

止め方: `node setup-helper.mjs stop mac`

### Windowsの場合（タスクスケジューラ）

1. 次を実行する。

   ```
   node setup-helper.mjs autostart win
   ```

   これで、`templates/run-hidden.vbs.template` の `{{BRIDGE_DIR}}` への値の埋め込み・`run-hidden.vbs`としての保存・タスクスケジューラへの登録（`schtasks /create`）までがまとめて行われる。
2. **管理者権限が無くコマンドでの登録が失敗した場合**は、次のGUI手順で登録する: 持ち主に「タスクスケジューラ」を開いてもらい、「基本タスクの作成」→ トリガーは「ログオン時」→ 操作は「プログラムの開始」→ プログラムに `wscript.exe`、引数に `run-hidden.vbs` の絶対パス（ダブルクォートで囲む）を指定する、と1画面ずつ案内する（`run-hidden.vbs`自体は直前の`node setup-helper.mjs autostart win`コマンドが既に書き出しているので、GUI登録だけ行えばよい）
3. 一度サインアウト・サインインして、自動で起動メッセージがDiscordに届くか確認する

止め方: `node setup-helper.mjs stop win`

持ち主向けに、やさしい言葉で次をまとめて伝える:

## トラブルシュート（切り分け表）

持ち主が「動かない」と言ったら、上から順に確認する。

| 症状 | 疑う原因 | 確認方法 | 直し方 |
|---|---|---|---|
| Botがそもそもオンラインにならない（Discordの一覧でグレー表示） | PCが起動していない／ネットに繋がっていない／プログラムが落ちている | PCの電源とネット接続を確認。`node bridge.mjs` を手動で起動しログを見る | PCを再起動、または自動起動の設定（手順6.6）を見直す |
| Botはオンラインで👀も付くが、返事に「許可がありません」「実行できません」のような文言が繰り返し出る | 手順6.5の許可設定がまだ済んでいない、または`.claude/settings.json`への追記が漏れている | `.claude/settings.json`の`permissions.allow`に手順6.5の項目が入っているか確認する | 手順6.5をやり直す。ワイルドカードでは絶対に済ませず、具体的なコマンド名で追記する |
| 起動ログに「トークンが見つかりません」 | `~/.config/ai-hisho/bot-token` が無い・空 | ファイルの存在を確認（中身は画面に出さない） | 手順2をやり直し、ファイルへ保存し直す |
| 起動ログに「Discordへのログインに失敗しました」 | トークンが間違っている・失効している | Developer Portalで「Reset Token」して再取得 | 手順2をやり直す |

| Botはオンラインで👀も付くが、返事だけ来ない・止まったまま | claude CLIが見つからない（PATHが通っていない環境から起動している）／timeoutMsが短すぎる | ログに「spawn error」や「ENOENT」が出ていないか確認 | `config.json` に `"claudeBin": "claudeの絶対パス（which claude / where claude で調べる）"` を追記する |
| 一部のチャンネルだけ反応しない | `channelIds` にそのチャンネルのIDが入っていない | config.jsonを確認 | チャンネルIDを追記（または@メンションで呼んでもらう。@メンションはどのチャンネルからでも反応する設計） |
| 特定の人にだけ反応しない | `allowedUsers` にそのユーザーのIDが登録されていない | config.jsonを確認 | `{"id":"...", "name":"..."}` を追記 |
